# Одностраничник-портфолио — дизайн

Дата: 2026-11-06
Статус: каркас (тексты и финальный дизайн — отдельными сессиями)

## Зачем

Одна ссылка, которую можно отправить работодателю или рекрутеру. Человек открывает
страницу и за 20–30 секунд понимает, кто это, что умеет и как связаться.

Аудитория: нанимающие и рекрутеры в IT/B2B. Язык сайта — только русский.

## Позиционирование

Из `vacancy-hunter/me/strategy.md`: «один человек — две сильные стороны».

1. **Тексты** — лонгриды для Хабра и VC, которые выходят в топ (141, 88, 71 тыс. просмотров).
2. **Инструменты** — сам собирает с ИИ и доводит до прода (`article-layout`, `factory`,
   `media-scan`, `vacancy-hunter`), ими пользуются нетехнические люди.

Обе ветки равноправны. Сверху — общая строка позиционирования, дальше два блока рядом
(на мобиле — друг под другом).

## Цели

- Адаптивная одна страница, читаемая с телефона и десктопа.
- Три темы: день, тёплая, ночь. Переключатель в шапке, выбор сохраняется.
- Лёгкая анимация появления секций и карточек; уважает `prefers-reduced-motion`.
- Весь контент — в одном файле, чтобы тексты менялись без правки вёрстки.
- Статическая сборка, которую можно положить на любой хостинг.

## Не-цели

- Настоящие тексты и финальный визуальный дизайн — следующая сессия.
- Английская версия, блог, CMS, формы с бэкендом, аналитика.
- Публикация и домен — решаем после каркаса.

## Стек

**Выбрано:** Vite + React + TypeScript + Tailwind CSS + Motion (framer-motion).

Рассмотренные альтернативы:
- **Astro** — меньше JS на клиенте, но переключатель тем и анимации всё равно требуют
  островков; для одной страницы выигрыш невелик.
- **Чистый HTML/CSS/JS** — ноль зависимостей, но добавление секций, карточек и смены темы
  усложняется по мере роста.

React выбран потому, что каркас делается один раз, а тексты потом правятся в data-файле:
дерево секций описывается данными, а не копипастой разметки.

## Структура страницы

1. **Шапка** — имя/инициалы, навигация по якорям, переключатель темы.
2. **Hero** — имя, одна строка позиционирования, две кнопки-якоря: «Тексты» и «Инструменты».
3. **О себе** — 3–4 строки.
4. **Две ветки** — сетка 2 колонки на десктопе:
   - «Тексты»: карточки статей (заголовок, площадка, просмотры, ссылка).
   - «Инструменты»: карточки проектов (что делает, стек, эффект, ссылка).
5. **Опыт** — короткий таймлайн (RuminLab, фриланс).
6. **Навыки** — чипы: контент, ИИ-автоматизация, веб.
7. **Контакты** — email, Telegram, телефон, кнопка «написать».
8. **Подвал** — год, «сделано на React».

## Темы

- Три палитры через CSS-переменные на `[data-theme="day" | "warm" | "night"]`.
- По умолчанию `day`; если у системы тёмная схема и пользователь ещё не выбирал —
  открываем `night`.
- Выбор хранится в `localStorage`, применяется до первой отрисовки (скрипт в `index.html`),
  чтобы не мигало.
- `color-scheme` выставляется вместе с темой.

## Анимация

- Появление секций: fade + сдвиг вверх, `whileInView`, один раз.
- Карточки: лёгкий stagger.
- Переход цветов темы — CSS transition.
- При `prefers-reduced-motion: reduce` анимации отключаются.

## Контент

`src/content.ts` содержит типизированные структуры: `profile`, `about`, `texts[]`,
`tools[]`, `experience[]`, `skills[]`, `contacts[]`. В каркасе — реальные данные из
профиля (имена проектов, статьи с просмотрами, контакты), но формулировки черновые
и помечены как заготовка.

## Сборка и деплой

- `npm run build` → статика в `dist/`.
- `base: './'` в Vite — сборка работает и из корня домена, и из подпапки (GitHub Pages).
- Хостинг и домен — позже.

## Решения, оставленные исполнителю

- Конкретные размеры, отступы и типографика — на усмотрение исполнителя, дизайн
  дорабатывается отдельно.
- Точный набор полей в карточках — минимально необходимый.
- Телефон на публичной странице: включён, если владелец не попросит убрать.
